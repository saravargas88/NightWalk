# NightWalk

Predicting nighttime street brightness from daytime street-level imagery.

## Overview

Street lighting shapes how safe a route feels at night, but tools like Google Maps have no way to account for it — nighttime street-level imagery is too scarce to map at scale. **NightWalk** predicts how bright a street will be at night using only a daytime photo, then demonstrates a downstream application: a lighting-aware pedestrian route planner.

The approach has two stages:

1. **Feature-aware backbone pretraining** — an EfficientNet-B0 backbone is pretrained on daytime images using weakly supervised labels (streetlight, tree canopy, and storefront counts/areas) generated by Grounding DINO, an open-vocabulary object detector.
2. **Brightness fine-tuning** — a regression head is attached to the backbone and fine-tuned end-to-end on 974 manually paired day–night images collected across New York City, predicting normalized nighttime brightness from a daytime image alone.

Full method, ablations, and results are in [`paper/NightWalk_Final_Report.pdf`](paper/NightWalk_Final_Report.pdf).

**Key result:** a linear baseline using only object counts fails to capture meaningful brightness signal (R² = 0.08). The fine-tuned model recovers real signal from the full image (R² = 0.46), though a controlled ablation shows our custom feature-based pretraining doesn't outperform standard ImageNet initialization — daytime scenes contain real nighttime-lighting signal, but it isn't reducible to simple object counts, and general-purpose visual features transfer surprisingly well.

## Dataset

~100,000 street-level images of Washington Square Park, NYC, captured via car-mounted camera. Images span multiple times of day. Metadata includes GPS coordinates, heading, and timestamp.

## Pipeline

### 1. Data collection & pairing
Nighttime images were captured on foot at the same locations/orientations as a subset of the original daytime fleet imagery, then matched to their daytime counterpart using a semi-automatic GPS-based pairing tool (`data_collection/map_matcher.py`).

See `data_collection/README.md` for full setup, usage, and the labeling workflow.

### 2. Day/night classification

The goal is to separate the ~100k images into a **night** bucket (usable as brightness ground truth) and a **day** bucket (usable as daytime proxy features). Classification is done in `labeling/day_night_classification` and the result is written to `labeling/day_night_classification/labels_final.csv`.

Initially, we wanted to use night photos in the dataset. However, since finding true nighttime phtos was difficult to automate (due to shifting sunset/sunrise times) and matching night photos to existing day photos proved difficult, we took our own night images. The `day_night_classification` folder houses our efforts to examine night imagery, but is largely not used in the final product. 

### 3. DINO feature labeling
Generates weakly supervised counts/areas for streetlights, trees, and storefronts on daytime images, used to pretrain the backbone. Also samples/prepares the daytime image pools used for pretraining.

Edit `MODE` and `COUNT_PROMPT_NAME` at the top of `dino_exps.py`, then:
```bash
cd dino_feature_detection
python dino_exps.py
```

- `MODE = "count"` — runs a single prompt on `SAMPLES` images, saves to `dino_counts/`
- `MODE = "grid"` — runs all prompts × all thresholds on `N_IMAGES` sample images, saves to `dino_grid/`

To add a new prompt, add an entry to `prompts.yaml` — no Python changes needed.

Outputs feed `model-training/pretraining/` for backbone pretraining, and `labeling/brightness_metrics/` for the brightness-metric baseline.

### 4. Backbone pretraining & Brightness fine-tuning
`model-training/run_experiments.py` is the main entry point — it fine-tunes the brightness model across all backbone conditions (ImageNet, DINO-counts (ours), SSL) and writes a results summary. Two things need to exist first:

```bash
cd splits && python make_split.py                                    # train/test splits
cd dino_feature_detection && python dino_exps.py                     # DINO feature counts
python model-training/pretraining/train_efficientnet_multihead.py    # dino_counts backbone (ours)

python model-training/run_experiments.py                             # full sweep, all backbones
```

Results land in `model-training/finetune-runs/`, summarized in `model-training/results_summary.csv`. See `model-training/README.md` for the full set of scripts (linear probe baseline, classification ablation, single-model training) and final results table.

### 5. Packaging for HPC training
`hpc/prepare_hpc_data.py` and `hpc/resize_for_hpc.py` package the minimal set of images, splits, and scripts needed to run training on a cluster, without uploading the full raw image dataset.

### 6. Demo: lighting-aware route planner
See `demo_app/README.md` for turning model predictions into routable lighting scores over Greenwich Village.

## Viewing results

Several steps above produce interactive HTML viewers. These load images/CSVs via `fetch()`, so **they must be served over a local web server** — opening the file directly (double-click, or `file://` in the browser) will fail with a security error.

```bash
cd /path/to/nightwalk
python3 -m http.server 8000
```

Then open in browser:
- `http://localhost:8000/labeling/legacy_brightness_exploration/darkest_viewer.html`
- `http://localhost:8000/labeling/legacy_brightness_exploration/evening_viewer.html`
- `http://localhost:8000/labeling/day_night_classification/review_tool.html` — manual label corrections
- `http://localhost:8000/labeling/day_night_classification/final_viewer.html` — final night/day split
- `http://localhost:8000/dino_feature_detection/proxy_viewer.html` — drop `dino_counts/*.csv` and `dino_counts/*.json`
- `http://localhost:8000/data_collection/pairing/pairs_viewer.html`
